# Room Plugins

A **Room Plugin** is a composable extension to a `Room`. Each plugin can contribute any subset of:

- **Message handlers** — merged into the room's `messages` map.
- **Lifecycle hooks** — `onCreate`, `onJoin`, `onLeave`, `onDispose` — composed with the room's own hooks (with configurable before/after ordering).
- **Public methods** — callable from the room as `this.plugins.<key>.someMethod()`.

The framework instantiates one plugin per room, wires `this.room` after the room is fully constructed, and merges everything in once per `Room` subclass (cached on the class — there's no per-instance setup cost).

## Attaching plugins to a Room

Use `definePlugins` inside your `Room` subclass:

```ts filename="MyRoom.ts"
import { Room, definePlugins } from "colyseus";
import { IdleKickPlugin } from "colyseus/plugins/idle-kick";

export class MyRoom extends Room {
  plugins = definePlugins({
    idle: new IdleKickPlugin({ timeoutMs: 60_000 }),
  });

  onCreate() {
    // your own setup — runs alongside the plugin hooks
  }
}
```

The key you choose (`idle`) is the handle you'll use to call back into the plugin from your room code (e.g. `this.plugins.idle.refresh(client)`).

## Writing your own plugin

Subclass `RoomPlugin` and override any subset of lifecycle hooks. `this.room` is wired automatically after the host room is fully constructed — don't access it from the plugin's constructor.

```ts filename="ChatPlugin.ts"
import { RoomPlugin, type Client } from "@colyseus/core";

export class ChatPlugin extends RoomPlugin {
  private history: string[] = [];
  private historyLimit: number;

  constructor(opts: { historyLimit: number }) {
    super();
    this.historyLimit = opts.historyLimit;
  }

  messages = {
    chat: (client: Client, msg: { text: string }) => {
      this.history.push(msg.text);
      if (this.history.length > this.historyLimit) { this.history.shift(); }
      this.room.broadcast("chat", { from: client.sessionId, text: msg.text });
    },
  };

  // Public — callable as `this.plugins.chat.getHistory()` from the room
  getHistory(): readonly string[] {
    return this.history;
  }
}
```

Use it like any other plugin:

```ts filename="MyRoom.ts"
import { Room, definePlugins } from "colyseus";
import { ChatPlugin } from "./ChatPlugin";

export class MyRoom extends Room {
  plugins = definePlugins({
    chat: new ChatPlugin({ historyLimit: 100 }),
  });

  onDispose() {
    console.log("final chat history:", this.plugins.chat.getHistory());
  }
}
```

## Lifecycle hook order

By default, plugins run **before** the room's hook for setup-style events and **after** for teardown-style events. Each plugin can override this per-hook via the `order` field.

| Hook        | Default order vs the room's own hook | Rationale                                  |
|-------------|--------------------------------------|--------------------------------------------|
| `onCreate`  | Plugins run **before**               | Plugins set up guards/state the room reads |
| `onJoin`    | Plugins run **before**               | Plugins can validate/decorate the client   |
| `onLeave`   | Plugins run **after**                | Capture the final state the room left      |
| `onDispose` | Plugins run **after**                | Run cleanup after the room's teardown      |

To override the default for a specific hook:

```ts filename="MyPlugin.ts"
import { RoomPlugin } from "@colyseus/core";

export class MyPlugin extends RoomPlugin {
  order = {
    onJoin: "after",   // run AFTER the room's onJoin instead of before
  } as const;

  onJoin(client) {
    // ...
  }
}
```

## Message handler rules

- A plugin's `messages` are merged into the room's `messages`.
- If the **room** defines the same message key as a plugin, the room wins — the plugin's handler is silently dropped. This is the documented escape hatch for _"use the plugin but override one message"_.
- If **two plugins** define the same key, the framework throws at class-init time naming both plugin keys. Resolve by giving one a different key or by overriding on the room's own `messages`.

## Typed access to room state

Plugins that need typed access to the host room's state should parameterize their generic with `<this>`:

```ts filename="LeaderboardsPlugin.ts"
import { RoomPlugin, type Room } from "@colyseus/core";

export class LeaderboardsPlugin<R extends Room<{ state: MyState }>> extends RoomPlugin<R> {
  onLeave(client) {
    // `this.room.state` is fully typed as MyState
    this.room.state.players.delete(client.sessionId);
  }
}
```

Then on the room:

```ts filename="MyRoom.ts"
plugins = definePlugins({
  leaderboards: new LeaderboardsPlugin<this>(),
});
```

## Testing a plugin in isolation

Use `attachToTestRoom` to inject a stub room and exercise the plugin's hooks without spinning up a full Colyseus server:

```ts filename="MyPlugin.test.ts"
import assert from "assert";
import { attachToTestRoom } from "@colyseus/core";
import { ChatPlugin } from "./ChatPlugin";

const plugin = new ChatPlugin({ historyLimit: 5 });
const broadcasts: any[] = [];
attachToTestRoom(plugin, {
  broadcast: (type, payload) => broadcasts.push([type, payload]),
});

plugin.messages.chat({ sessionId: "alice" } as any, { text: "hi" });
assert.deepEqual(broadcasts, [["chat", { from: "alice", text: "hi" }]]);
assert.deepEqual(plugin.getHistory(), ["hi"]);
```

The second argument is shallow-merged onto the stub, so tests only declare the room properties they actually exercise.
