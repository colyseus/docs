# Admin Panel

The **Colyseus Admin Panel** (`@colyseus/admin`) is a browser-based operations console for any project using [`@colyseus/database`](/database). It bundles user management (browse, ban, revoke sessions), generic CRUD over your drizzle tables, a live room inspector, and a customizable dashboard — all behind session-based admin login with role-based access control and an append-only audit log.

For a lightweight, no-auth dashboard intended for casual room and process inspection, see the [Monitoring Panel](/tools/monitoring) instead. The admin panel is the heavier counterpart, intended for production operations and game-team workflows.

## Installation

`@colyseus/admin` depends on [`@colyseus/database`](/database) (for the user store, audit log, and drizzle table introspection) and [`@colyseus/auth`](/auth/module) (for JWT signing and password hashing). Both are peer dependencies; install them together if you haven't already:

```sh npm2yarn
npm install --save @colyseus/admin @colyseus/database @colyseus/auth
```

## Mounting

The admin panel can be mounted in two ways — pick the one that matches your stack:

<Tabs items={["Standard router (recommended)", "Express middleware"]}>
    <Tabs.Tab>
    Spread `admin({})` into `createRouter`. The factory returns both the SPA static-serving routes and the REST API in one map:

    ```ts {3,10} filename="src/app.config.ts"
    import { defineServer, createRouter } from "colyseus";
    import { GameDatabase } from "@colyseus/database";
    import { admin } from "@colyseus/admin";

    export const db = new GameDatabase({ connectionString: process.env.DATABASE_URL });

    export default defineServer({
        database: db,
        routes: createRouter({
            ...admin({}),
        }),
    });
    ```
    </Tabs.Tab>

    <Tabs.Tab>
    Use this mode if you rely on existing Express middleware or libraries. The return value of `admin(...)` is also a valid Express middleware:

    ```ts {2,6-7} filename="src/app.config.ts"
    import { defineServer } from "colyseus";
    import { admin } from "@colyseus/admin";

    export default defineServer({
        database: db,
        express: (app) => {
            app.use("/", admin({}));
        },
    });
    ```
    </Tabs.Tab>
</Tabs>

<Callout type="info">
    The `database` option defaults to `GameDatabase.current` — set automatically when you construct `new GameDatabase(...)`. Multi-database deployments should pass `database` explicitly (e.g. `admin({ database: db })`) to disambiguate which instance the panel drives.
</Callout>

## First-run bootstrap

The admin panel ships with **no built-in admin user**. The first time anyone visits `/admin`, the UI checks for the existence of any admin account and — if none exists — renders a one-time bootstrap form.

After bootstrap:

- A session cookie is set (HttpOnly, SameSite=Strict, JWT-signed).
- You're redirected into the panel with full `admin` role access.
- All sibling routes gated with `admin.guard()` (e.g. the Playground or Monitor) now resolve against the same session.

<Callout type="info">
    See [Authentication & RBAC](/admin/authentication) for the full session, role, and revocation story.
</Callout>

## Usage

Once mounted, start your server and navigate to `http://localhost:2567/admin` in your browser. If you customized `uiPath`, adjust the URL accordingly.

The REST API mounts in parallel at `http://localhost:2567/admin-api` and is consumed by the SPA — you generally don't call it directly, but the endpoints are normal `createEndpoint(...)` routes and respect the same `admin.guard()` semantics if you wrap them.

## Hardening for production

The defaults are tuned for local development. Before exposing the panel to the public internet:

- **Set a strong `JWT_SECRET` and `SESSION_SECRET`** — see [Auth Module → Required Environment Secrets](/auth/module#required-environment-secrets). Rotating either invalidates all admin sessions.
- **Wire [`auth.settings.onResetPassword`](/auth/module#on-reset-password)** to deliver password reset emails through your transactional email provider — the same hook that powers your player-side reset flow.
- **Tighten the session cookie** via the `session` option — set an explicit `domain`, longer or shorter `maxAge` to taste, and confirm `Secure`/`SameSite` flags match your deployment.
- **Disable `allowDevHeader`** if you don't explicitly need it. It auto-disables when `NODE_ENV === "production"`, but set it to `false` explicitly if you're unsure.
- **Swap the in-memory rate limiters for a Redis-backed implementation** on multi-process deployments — the default token buckets don't share state across instances.
- **Gate the Monitor and Playground** behind `admin.guard()` so you don't have multiple unauthenticated panels exposed:

    ```ts filename="src/app.config.ts"
    routes: createRouter({
        ...playground({ use: [admin.guard()] }),
        ...monitor({    use: [admin.guard()] }),
        ...admin({}),
    }),
    ```

## Options reference

`admin(options)` accepts the following `AdminOptions`:

| Option | Type | Default | Description |
|---|---|---|---|
| `database` | `GameDatabase` | `GameDatabase.current` | The database powering the user store, audit log, and table introspection. Pass explicitly for multi-database setups. |
| `tables` | `Record<string, Table>` | `database.tables` | Map of drizzle tables exposed in the panel. Spread `database.tables` and append custom tables: `{ ...database.tables, guilds }`. |
| `resources` | `Record<string, ResourceDefinition>` | `{}` | Per-table UI/UX overrides — labels, visible columns, form fields, actions, policies. See [Resources & CRUD](/admin/resources). |
| `uiPath` | `string` | `"/admin"` | Mount path for the admin SPA. |
| `apiPath` | `string` | `"/admin-api"` | Mount path for the admin REST API. |
| `uiDistDir` | `string` | _built-in_ | Absolute path to the built UI assets. Defaults to the bundled `build/` directory inside the package. |
| `session` | `SessionConfig` | _see below_ | Cookie config: `maxAge`, `domain`, `sameSite`, `secure`. |
| `resolveUserId` | `(ctx) => Promise<string \| undefined>` | session cookie → `X-User-Id` (dev) | Override the identity resolver to integrate with another auth scheme. |
| `enforceRbac` | `boolean` | `true` | Set to `false` to skip RBAC entirely (development only). |
| `allowDevHeader` | `boolean` | `true` in dev, `false` in prod | Permit `X-User-Id: <id>` as a fallback identity for curl/puppeteer testing. |
| `minPasswordLength` | `number` | `8` | Minimum password length accepted by bootstrap and reset endpoints. Plain length check — layer on stronger rules in `onResetRequest` if needed. |
| `onResetRequest` | `(ctx) => void \| Promise<void>` | logs to stdout | Panel-specific override for the password-reset email. Most projects should configure [`auth.settings.onResetPassword`](/auth/module#on-reset-password) instead and reuse their player-side delivery. Receives `{ email, userId, token, url }`. |
| `rateLimit` | `{ login, bootstrap, requestReset }` | in-memory token buckets | Per-endpoint rate limiters. Pass `false` per slot to disable, or a custom `RateLimiter` to swap in a Redis-backed implementation. |
| `dashboard` | `{ presets, widgets }` | all presets enabled | Configure the dashboard homepage. See [Dashboard & widgets](/admin/dashboard). |
| `logger` | `Logger \| null` | JSON stdout | Pino-compatible logger. Pass `null` to silence the panel's internal logs. |

### Session defaults

The `session` config controls the JWT cookie. Defaults:

```ts
session: {
    maxAge: 7 * 24 * 60 * 60, // 1 week (seconds)
    sameSite: "strict",
    secure: process.env.NODE_ENV === "production",
    // domain: undefined  ← set explicitly when serving from a subdomain
}
```

The cookie is always `HttpOnly` and signed with `JWT_SECRET`. Revoking a session is done via `db.auth.bumpTokenVersion(userId)` — see [Database → Authentication](/database#authentication-built-in-colyseusauth-integration).
