# Colyseus documentation

Source for [docs.colyseus.io](https://docs.colyseus.io). Built with
[Fumadocs](https://fumadocs.dev) on Next.js and exported as a static site to
Netlify.

## Local development

```bash
pnpm install   # also installs the pre-commit hook
pnpm dev       # http://localhost:3000
pnpm build     # generates the nav surface, builds out/, places the markdown twins
pnpm start     # serves out/ as Netlify would
```

Prose linting needs [Vale](https://vale.sh/docs/install), a single Go binary
that is deliberately not an npm dependency:

```bash
brew install vale
```

Without it, `pnpm lint:prose` warns and exits 0. CI always runs it.

## Where things live

| Path | What |
| --- | --- |
| `content/docs/` | Every page, as `.mdx`. A `(name)` folder groups pages without adding to the URL. |
| `content/docs/**/meta.json` | Sidebar order, separators (`"---Title---"`), folder titles and icons. |
| `components/mdx.tsx` | Every component a page can use. Pages import nothing. |
| `lib/source.ts` | The Fumadocs loader: routes, page tree, markdown twins. |
| `lib/llms-markdown.ts` | How each component reads in the `.md` twins. |
| `public/_redirects` | Old URLs → current pages, served by Netlify as 301s. |
| `site.config.json` | Site URL, docs version, repository. |

## Writing a page

Frontmatter `title` is the page heading, the `<title>`, and the sidebar label.
Don't repeat it as a `# H1` in the body. Optional fields:

| Field | Use |
| --- | --- |
| `description` | Meta description and llms.txt summary. Every page has one. |
| `sidebarTitle` | Shorter sidebar label when `title` is long. |
| `icon` | Sidebar icon: an octicon name (`PeopleIcon`) or `logo:unity`. |
| `movedAnchors` | Old heading slug → new `/path#anchor`. See the `move-page` skill. |

Components worth knowing, all available without an import:

- `<LangTabs>` with `<Tab value="TypeScript">`: the SDK language switcher. One
  choice persists across the whole site. Values: TypeScript, JavaScript, C#,
  Lua, Haxe, GDScript, Dart.
- `<Tabs>` with `<Tab value="…">`: any other tabs. Add `groupId` and `persist`
  to sync a set across pages, as `schema-style` does.
- `<Callout type="info|warning|error">`, `<Cards>` / `<Card>`, `<Steps>`
  (headings inside become steps), `<Files>` / `<Folder>` / `<File>`.
- A ```` ```npm ```` fence becomes npm/pnpm/yarn/bun tabs.
- Code fences take `title="file.ts"` and `{1,3-5}` line highlights.

## Checks

| Command | What it proves |
| --- | --- |
| `pnpm check-links` | Every internal link **and anchor** resolves against the heading ids the site renders, `movedAnchors` and `public/_redirects` are sound, and pages follow the content conventions (no imports, no links in headings, valid tab values). `next build` checks none of this. |
| `pnpm check:ai-nav` | The committed `llms.txt` and `robots.txt` match the sidebar, and every page is in the sidebar. |
| `pnpm lint:prose` | Vale over `content/docs/`. Terminology and em-dash violations are errors and gate CI; everything else is advisory. |
| `pnpm types:check` | TypeScript over the app, components, and config. |

The first three run as a pre-commit hook, installed by `pnpm install` via
`core.hooksPath`. Use `git commit --no-verify` to skip them.

## Generated files

`public/llms.txt`, `public/sitemap.xml`, and `public/robots.txt` are generated by
`scripts/generate-ai-nav.js` from the page tree and page frontmatter. Edit the
pages, run `pnpm generate:ai-nav`, and commit the result. Never hand-edit the
three outputs.

`pnpm build` also writes an `out/<route>.md` markdown twin of every page plus
`out/llms-full.txt`, so any docs URL with `.md` appended returns raw markdown.
Those artifacts are not committed.

`.git-blame-ignore-revs` lists commits that touched every page without changing
what it says. GitHub's blame skips them; run
`git config blame.ignoreRevsFile .git-blame-ignore-revs` to do the same locally.

## Conventions

- [`STYLE.md`](./STYLE.md) is the house style guide: sentence limits, voice, the
  approved terminology table, and the rules we deliberately reject so they do
  not get reintroduced as improvements.
- [`CLAUDE.md`](./CLAUDE.md) carries the instructions for coding agents, and
  `.claude/skills/` holds the repo's recurring rituals: moving a page without
  breaking inbound links, auditing a page against the framework source, and
  reviewing a docs diff.
